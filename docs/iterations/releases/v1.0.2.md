# AtomBox v1.0.2 迭代说明

## 1. 迭代目标

v1.0.2 聚焦运行中对象存储传输的真实取消。任务收到取消请求后进入 `Canceling`，只有底层请求退出并完成必要清理后，Transfer 才写入最终 `Canceled` 并释放并发槽位。

本次支持范围：

| Provider | 上传取消 | 下载取消 | 实现方式 |
| --- | --- | --- | --- |
| 通用 S3 | 支持 | 支持 | AWS SDK 请求级 `CancellationToken`；分片取消执行 Abort Multipart |
| 腾讯云 COS | 支持 | 支持 | SDK `Cancel(CosRequest)`、可取消正文流和回调完成确认；分片取消执行 Abort Multipart |
| 七牛 Kodo | 暂不支持 | 支持 | `HttpClient` 响应头优先模式和流式复制取消 |

阿里云 OSS、百度 BOS、华为云 OBS、火山引擎 TOS、又拍云 USS 等 Provider 本次不修改。京东云 OSS 和青云 QingStor 的代码继续保留，但 Desktop 添加账号入口继续隐藏。

## 2. 设计与实现

### 2.1 通用 S3

- 在共享 S3 适配层增加内部可选接口 `ICancellableS3TransferClient`，不修改 Core 公共契约，也不要求其他 S3 兼容客户端同步迁移。
- `AwsSdkS3CompatibleClient` 将任务 Token 传给 PutObject、GetObject、InitiateMultipartUpload、UploadPart 和 CompleteMultipartUpload 请求。
- 取消或分片失败后使用独立的 10 秒清理令牌执行 `AbortMultipartUpload`，不复用已经取消的任务令牌。
- `S3CompatibleProvider` 仅在客户端实现可取消接口时选择异步路径；百度、华为、火山等现有客户端继续使用原路径。

### 2.2 腾讯云 COS

- 在 `CosXmlServer` 前增加内部异步请求适配边界，将官方 SDK 回调包装为 Task，并在取消时调用 `Cancel(CosRequest)`。
- 普通上传使用任务令牌感知的只读流。令牌在底层同步读取期间取消时，已读数据不会继续交给 SDK。
- SDK 请求取消后等待失败/成功回调；上传也接受正文流已经观察到取消作为停止证据。
- 10 秒内无法确认请求退出时，任务仍归类为 `Canceled`，但状态原因提示远端最终状态可能未知。
- 分片上传保存 Upload ID；取消后停止活动请求并使用独立清理令牌执行 Abort，Abort 完成前不释放任务槽位。

### 2.3 七牛 Kodo

- 下载不再通过 `ReadAsByteArrayAsync` 将完整对象预先载入内存。
- `QiniuKodoDownloadObject` 持有响应流和 `HttpResponseMessage`，由 Provider 完成复制或取消后统一释放。
- HTTP 请求、响应流读取和目标流写入均传播任务 Token。
- 七牛 SDK 8.7.0 的上传控制器不能提供可验证的请求级退出和服务端 Abort，因此上传取消不纳入本次稳定能力。

### 2.4 状态和竞态

- 用户取消与应用退出继续使用不同语义；前者最终为 `Canceled`，后者为 `Interrupted`。
- 服务端成功回调先完成时，任务为 `Succeeded`，迟到的取消不得覆盖成功。
- Abort 失败或超时不把用户取消改成普通失败；最终仍为 `Canceled`，并在 `StatusReason` 中提示可能残留未完成分片。
- Desktop、Application、Core、Infrastructure 和 Transfer 公共接口不新增 Provider 专用类型。

### 2.5 弱取消 Provider 的交互收口

- Desktop 根据 `ProviderId + TransferDirection` 区分精准取消和尝试取消，不修改 Provider、Transfer、Infrastructure 或 Core 的执行契约。
- 通用 S3、腾讯 COS、FTP、SFTP、WebDAV 的上传和下载，以及七牛 Kodo 下载继续显示“取消”，直接进入现有精准取消链路。
- 阿里云 OSS、百度 BOS、华为云 OBS、火山引擎 TOS、又拍云 USS、七牛 Kodo 上传，以及未知或当前隐藏的 OSS Provider，运行中任务显示“尝试取消”。
- 用户点击“尝试取消”后，Desktop 先提示该存储服务不能保证即时停止，当前请求可能继续执行，远端文件最终状态需要刷新目录确认；用户确认后才调用现有取消入口。
- 弱取消任务处于 `Canceling` 时显示“正在尝试取消”。底层最终成功则任务如实显示成功；底层响应取消则显示已取消，不伪造远端结果。
- Pending 任务尚未进入 Provider，不受弱取消限制，始终可以直接取消且不显示风险确认。

## 3. 测试与验收

### 3.1 自动化测试

- Provider 单元测试覆盖 AWS Token 传递、普通上传/下载取消、分片 Abort、Abort 失败告警和非可取消 S3 客户端兼容路径。
- COS 单元测试覆盖回调 Task 包装、`Cancel(CosRequest)`、普通上传/下载取消、分片 Abort、清理失败告警和成功优先竞态。
- 七牛测试覆盖下载响应流不预缓冲、响应所有权释放、正文复制取消和统一 `Canceled` 错误映射。
- Provider 契约测试验证取消结果仍使用 `StorageErrorCategory.Canceled`，不改变 Core 的 `IStorageProvider` 输入输出约定。

## 4. 已知限制

- 腾讯 COS 官方 SDK 的回调 API 在启动阶段可能同步读取上传流，AtomBox 通过可取消流阻止继续发送，但 SDK 本身没有统一的可等待取消句柄。
- COS 请求在 10 秒内无法确认退出时会结束为带告警的 `Canceled`；此时不得向用户承诺远端绝对不存在对象。
- 七牛上传、其他 OSS Provider 的运行中取消仍不属于稳定能力。
- 弱取消 Provider 的提示只表达 AtomBox 已接受取消意图，不承诺同步 SDK 请求立即停止或远端对象一定不存在。
- 本次只覆盖上传和下载；列表、搜索、复制、移动、重命名和删除不属于传输队列取消范围。
