# AtomBox v1.0.1 迭代计划

> 文档状态：Implemented
>
> 创建时间：2026-08-04
>
> 最近更新：2026-08-05
>
> 范围：新增基于 AWS 官方 .NET SDK 的通用 S3 兼容对象存储 Provider。

## 1. 背景与现状

AtomBox 已支持阿里云 OSS、百度云 BOS 等对象存储，并具备可复用的 `S3CompatibleProvider`、`IS3CompatibleClient` 和对象存储浏览能力。现有部分厂商 Provider 使用官方 SDK，部分兼容实现使用项目内的 AWS Signature V4 客户端。

v1.0.1 新增面向 MinIO、Ceph RGW 及其他 S3 兼容服务的通用入口。该入口不绑定具体厂商品牌，优先使用 AWS 官方 .NET SDK，不继续扩展项目内手写签名与 HTTP 协议实现。当前真实性测试结论仅覆盖 MinIO 路径寻址模式；Amazon S3、Ceph RGW 和其他兼容实现仍属于协议层预期兼容对象，不能据此宣称已经完成真实性验收。

## 2. 版本目标

- 用户可以通过 Endpoint、Region 和凭据添加使用路径寻址的 S3 兼容存储账号。
- 请求固定使用路径寻址，支持局域网 IP、非默认端口，并以 MinIO 作为本版本已经验证的兼容基线。
- Desktop 本版本只开放长期 AK/SK 认证，与其他 OSS Provider 的账号表单保持一致。
- 账号根目录固定列出当前凭据可见的全部 Bucket。
- 通用 S3 具备与现有 OSS Provider 一致的浏览、上传、下载、删除、文件夹和移动能力。
- 通过局域网中的真实 MinIO 完成 headless 全链路真实性测试。

## 3. 本版本范围

| 功能 | 状态 | 主要模块 |
|---|---|---|
| 注册通用 S3 Provider | Implemented | Providers、Desktop |
| AWS 官方 S3 SDK 客户端适配 | Implemented | Providers |
| 固定路径寻址模式 | Implemented | Providers |
| AK/SK 用户认证 | Implemented | Providers、Desktop |
| Session Token 内部兼容能力 | Implemented（UI 未开放） | Providers |
| 根目录 Bucket 列表 | Implemented | Providers、Desktop |
| 通用 S3 账号连接测试 | Implemented | Providers、Application（复用现有流程） |
| 文件浏览与对象操作 | Implemented | Providers（复用现有通用对象存储逻辑） |
| 单元测试与局域网真实性测试 | Implemented | Providers.Tests、EndToEnd.Tests |

## 4. 模块边界

### 4.1 需要修改

- `AtomBox.Providers`
  - 注册通用 S3 Provider。
  - 新增 AWS 官方 SDK 客户端适配器。
  - 将通用 S3 配置转换为 `AmazonS3Config` 和 AWS 凭据对象。
  - 实现 Bucket 列表、异常映射及配置校验。
- `AtomBox.Desktop`
  - 在添加 OSS 账号的供应商列表中显示“通用 S3 / S3 Compatible”。
  - 增加通用 S3 的配置项、凭据项和本地化文案。
- `AtomBox.Providers.Tests`
  - 增加配置、注册、客户端创建和真实服务测试。
- `AtomBox.EndToEnd.Tests`
  - 使用隔离应用数据目录和真实组合根验证 Application、Transfer、Infrastructure、Providers 到 MinIO 的完整链路。
- `Directory.Packages.props`
  - 集中声明 `AWSSDK.S3` 包版本。

### 4.2 原则上不修改

- `AtomBox.Core`：现有 Provider 配置字典、凭据字典和对象存储端口足够表达本需求，不新增公共模型。
- `AtomBox.Application`：复用现有添加账号和连接测试编排；仅在实现中发现通用缺陷时才做与 Provider 无关的修正。
- `AtomBox.Transfer`：继续使用现有上传、下载任务模型。
- `AtomBox.Infrastructure`：不新增持久化结构，配置与凭据继续走现有存储机制。

现有阿里云、百度云及其他厂商 Provider 的 SDK、签名和行为不得迁移或改变。本版本只新增 `s3-compatible`。

## 5. Provider 稳定契约

### 5.1 基本信息

| 项目 | 值 |
|---|---|
| Provider ID | `s3-compatible` |
| 中文名称 | 通用 S3 |
| 英文名称 | S3 Compatible |
| Provider 类型 | OSS / Object Storage |

Provider ID 是持久化契约，发布后不得因 UI 名称调整而改变。

### 5.2 能力声明

通用 S3 声明以下现有能力：

- 列出 Bucket 和对象。
- 上传、下载、删除对象。
- 创建文件夹标记。
- 重命名和移动对象或前缀。
- 分片上传。

S3 没有真实目录。目录继续表示为对象 Key 的前缀；创建目录写入以 `/` 结尾的零字节标记对象，删除、移动和重命名目录沿用 AtomBox 已有的前缀递归语义。

### 5.3 兼容性与成熟度

| 使用范围 | v1.0.1 结论 |
|---|---|
| MinIO + 路径寻址 | 已完成真实性和全链路测试，可以作为当前稳定支持对象 |
| Amazon S3 | 使用 AWS 官方 SDK，理论上具备协议兼容基础，但尚无真实 AWS 账号验收 |
| Ceph RGW 及其他 S3 兼容服务 | 尚未进行真实性测试，需要按具体实现逐项验证 |
| 虚拟主机寻址 | 不支持 |
| pending 任务取消 | 已验证 |
| 正在运行的 S3 传输取消 | 不保证立即中断远端请求，不作为 v1.0.1 稳定能力 |

对象存储中的文件夹移动、重命名和递归删除需要逐个列举、复制或删除对象。现有 MinIO 测试已经验证功能正确性和超过 1000 个对象时的分页边界，但操作耗时及 API 请求量仍会随对象数量线性增长。

## 6. 配置与凭据

### 6.1 Provider 配置

| 配置键 | 必填 | 默认值 | 规则 |
|---|---:|---|---|
| `endpoint` | 是 | 无 | 完整的 `http://` 或 `https://` 绝对地址；允许非默认端口；不允许 path、query 或 fragment |
| `region` | 是 | 无 | 作为签名 Region；必须由用户按目标服务配置显式填写，例如服务要求的 `auto` |

示例：

```text
endpoint=http://100.64.0.32:9000
region=<required-region>
```

配置规范：

- `endpoint` 只描述服务根地址，不拼接 Bucket 名称。
- 局域网测试允许 HTTP；生产环境建议 HTTPS。
- AtomBox 不提供忽略 TLS 证书错误的选项。
- S3 请求固定采用路径寻址，Bucket 名称拼接在服务根地址之后。
- v1.0.1 不支持要求 Bucket 子域名的虚拟主机寻址服务。

### 6.2 凭据

| 凭据键 | 必填 | 说明 |
|---|---:|---|
| `accessKeyId` | 是 | Access Key ID |
| `accessKeySecret` | 是 | Secret Access Key |
| `sessionToken` | 内部保留 | 临时凭据的 Session Token；v1.0.1 Desktop 不提供输入入口 |

- 未填写 `sessionToken` 时创建 `BasicAWSCredentials`。
- 填写 `sessionToken` 时创建 `SessionAWSCredentials`。
- v1.0.1 的公开账号表单只保存 AK/SK；`sessionToken` 仅保留为 Providers 内部兼容键，不构成本版本公开认证功能。
- 三项凭据均按现有敏感信息机制保存，不进入普通配置、日志、错误详情或测试输出。
- 不使用本机 AWS Profile、环境变量凭据链或实例角色隐式替代用户填写的账号凭据。

## 7. Providers 实现设计

### 7.1 依赖

- 在 `Directory.Packages.props` 中统一声明 `AWSSDK.S3` `4.0.101.7`。
- Providers 项目只引用集中版本，不在项目文件中重复写版本号。

### 7.2 客户端适配

新增内部 AWS SDK 适配器，实现现有 `IS3CompatibleClient` 中立接口，并由 `S3CompatibleProvider` 复用。适配器负责：

- 将 AtomBox 请求映射为 AWS S3 SDK 请求。
- 将 SDK 响应转换为现有对象、Bucket、分页和分片结果。
- 下载保持流式读取，不将完整对象预先载入内存。
- 正确释放 `AmazonS3Client`、对象响应流和分片上传资源。
- 在现有接口允许的范围内传播超时和操作开始前的取消状态；AWS SDK 请求执行期间尚未完整贯穿取消令牌。

不修改现有厂商客户端对 `IS3CompatibleClient` 的实现方式，也不将它们切换到 AWS SDK。

### 7.3 SDK 配置映射

创建 `AmazonS3Client` 时：

- `AmazonS3Config.ServiceURL = endpoint`。
- `AmazonS3Config.AuthenticationRegion = region`。
- `AmazonS3Config.ForcePathStyle = true`，不读取或持久化寻址模式配置。

连接测试和正式操作必须使用同一套客户端工厂，避免“测试成功、实际浏览失败”的配置分叉。

### 7.4 Bucket 列表行为

- Provider 根目录固定调用 `ListBuckets`，展示当前凭据可见的 Bucket。
- 连接测试同样从根目录执行 Bucket 列表请求，确保测试与正式浏览行为一致。
- 凭据必须具备列出 Bucket 的权限；仅允许访问单个 Bucket 且没有 `ListBuckets` 权限的账号不属于 v1.0.1 支持范围。

### 7.5 错误映射

统一处理 `AmazonS3Exception`、AWS SDK 客户端异常、网络异常和取消异常：

| 场景 | AtomBox 错误类别 |
|---|---|
| 凭据错误、签名不匹配 | `Authentication` |
| 访问被拒绝 | `Authorization` |
| Bucket 或对象不存在 | `NotFound` |
| Endpoint、DNS、连接、TLS 失败或请求超时 | `Network` |
| 可观察到的用户取消 | `Canceled` |
| 无法归类的服务端错误 | `Provider` |

用户摘要应包含可行动信息；错误详情保留 HTTP 状态、AWS Error Code、Request ID 和安全的上下文。任何输出不得包含 Secret Access Key、Session Token、Authorization Header 或签名查询参数。

## 8. Desktop UI 设计

添加通用 S3 账号时显示：

- Endpoint：必填文本框，占位示例 `https://s3.example.com:9000`。
- Region：必填文本框，不提供默认值或隐式回退。
- Access Key ID：必填文本框。
- Secret Access Key：必填密码框。

交互要求：

- 缺失必填项或格式错误时，通过现有顶部 Message 统一提示。
- Desktop 不显示 Session Token 字段；后端保留的 Token 仍按敏感信息处理。
- 中英文切换立即更新新增文案，遵守现有多语言机制。
- 京东云和青云继续保持隐藏，本需求不改变其状态。

## 9. 测试设计

### 9.1 自动化单元测试

至少覆盖：

- Registry 能通过 `s3-compatible` 创建正确 Provider。
- Provider ID、名称、类型和能力声明正确。
- Endpoint 合法性、端口、禁止 path/query/fragment 的校验。
- Region 缺失时拒绝创建 Provider，以及显式配置值的映射。
- AWS SDK 配置始终启用 `ForcePathStyle`。
- 虚拟主机模式拒绝 IP Endpoint。
- 无 Token 使用基本凭据，有 Token 使用会话凭据。
- 根目录调用 `ListBuckets` 并返回当前凭据可见的 Bucket。
- AWS SDK 异常到 AtomBox 错误模型的映射。
- 日志和错误文本不包含凭据及签名信息。

### 9.2 局域网 headless 真实性测试

真实性测试入口可以连接 MinIO、Ceph RGW 或其他 S3 兼容实现，但 v1.0.1 已执行并形成验收结论的环境仅为局域网 MinIO。测试默认不运行，通过 `.local/generic-s3.env.ps1` 注入配置；该文件不得提交到 Git。

```powershell
$env:ATOMBOX_TEST_GENERIC_S3 = "1"
$env:ATOMBOX_GENERIC_S3_ENDPOINT = "http://192.168.0.105:9000"
$env:ATOMBOX_GENERIC_S3_REGION = "<required-region>"
$env:ATOMBOX_GENERIC_S3_BUCKET = "atombox-test"
$env:ATOMBOX_GENERIC_S3_ACCESS_KEY_ID = "..."
$env:ATOMBOX_GENERIC_S3_ACCESS_KEY_SECRET = "..."
$env:ATOMBOX_GENERIC_S3_SESSION_TOKEN = ""
$env:ATOMBOX_GENERIC_S3_TEST_PREFIX = "atombox/v1.0.1"
```

真实性测试覆盖：

1. 连接测试及根目录 Bucket 列表。
2. Bucket 根目录和前缀分页列举。
3. 小文件上传、流式下载及内容校验。
4. 文件夹标记创建和显示。
5. 文件及目录的重命名、移动。
6. 文件及递归目录删除。
7. 超过单页数量后的分页完整性。
8. 大文件分片上传及下载校验。
9. 文本和图片预览、大小限制及内容一致性。
10. Transfer 上传下载、批量任务、队列、历史、pending 取消和失败重试。
11. 指纹开关、SHA-256 计算、成功写入索引和重复上传查询。
12. 错误凭据、错误 Endpoint 格式和不存在对象的错误分类；无权限 Bucket 需要另行提供受限凭据。

路径模式是局域网真实性测试的必测基线。Session Token 仅保留 Providers 单元测试，不要求 v1.0.1 Desktop 或 MinIO 真实性测试开放该认证方式。

上述真实性测试结果只能证明对应 Endpoint 和服务实现的实际行为。MinIO 测试通过不得自动外推为 Amazon S3、Ceph RGW 或任意第三方 S3 兼容产品已经通过。

测试对象必须写入 `ATOMBOX_GENERIC_S3_TEST_PREFIX/e2e-<run-id>/` 下。按本项目真实性测试约定保留代表性测试数据及 `_evidence/manifest.json` 供人工核验；递归删除用例只删除本次运行创建的 `delete-cases/`，不清理用户已有数据，也不操作隔离前缀之外的对象。测试创建的临时 Bucket 在验证后立即清空并删除。

## 10. 非目标

- 不支持 AWS Signature V2。
- 不支持匿名 S3 账号。
- 不支持虚拟主机寻址；需要 `<bucket>.<endpoint-host>` 的服务不属于 v1.0.1 支持范围。
- 不在 v1.0.1 Desktop 开放 Session Token，也不主动调用 STS 获取或刷新临时凭据。
- 不支持 AWS Profile、SSO、AssumeRole 或自动凭据链。
- 不新增预签名 URL、Bucket Policy、版本控制、Object Lock 或 S3 Express 管理界面。
- 不提供跳过 HTTPS 证书校验的配置。
- 不迁移或重构现有阿里云、百度云及其他厂商 Provider。
- 不保证兼容服务未实现的 AWS S3 扩展特性。
- 不承诺兼容全部 S3 服务端实现，也不把 AWS 官方 SDK 等同于真实 Amazon S3 验收。
- 不保证正在运行的 S3 上传或下载能够立即响应用户取消；运行中 OSS 取消需要后续单独改造和验证。

## 11. 验收标准

- 中英文界面均可新增、编辑、连接测试和删除通用 S3 账号。
- 固定路径模式可以连接已验证的局域网 MinIO IP 和非默认端口。
- Desktop 新增和编辑通用 S3 账号时只显示 AK/SK；Providers 内部保留的 AK/SK/Session Token 由正确的 AWS 凭据类型承载。
- 账号根目录和连接测试均能列出当前凭据可见的 Bucket。
- 浏览、上传、下载、删除、目录操作、移动和分片上传已在 MinIO 中通过真实性测试。
- 连接测试和正式浏览使用相同客户端配置，不出现测试成功后配置无效的问题。
- 错误分类准确，UI 与日志不泄露敏感信息。
- 现有对象存储、FTP/SFTP、WebDAV 的自动化测试无回归。
- Windows、macOS 和 Linux Release 构建通过。

## 12. 实施顺序

1. 引入集中管理的 AWS S3 SDK 依赖。
2. 实现配置解析、校验、凭据创建和 SDK 客户端工厂。
3. 实现 `IS3CompatibleClient` 的 AWS SDK 适配器及错误映射。
4. 注册 `s3-compatible` 并接入 `S3CompatibleProvider`。
5. 实现根目录 Bucket 列表和连接测试行为。
6. 增加 Desktop 表单、供应商入口和中英文资源。
7. 完成单元测试和局域网真实性测试。
8. 执行全量回归、跨平台构建和人工 UI 验收。

## 13. 发布前检查

- 确认 AWS SDK 许可证、版本和包体积增量可接受。
- 确认所有新增配置键和 Provider ID 在保存、读取及升级后保持稳定。
- 验收账号根目录及连接测试的 Bucket 列表行为。
- 使用 IP Endpoint 和非默认端口验收固定路径模式。
- 检查 Session Token、错误详情和调试日志的脱敏。
- 检查保留的真实性测试对象仅位于隔离前缀。
- 记录最终测试数量、真实性测试环境、包体积变化和已知兼容性限制。
- Release 文案使用“通用 S3 Provider，已验证兼容 MinIO”，不得写成“完全兼容 Amazon S3”或“兼容全部 S3 服务”。

## 15. 实施结果

- 已通过 `AWSSDK.S3` `4.0.101.7` 接入 `s3-compatible`，现有厂商 Provider 未迁移 SDK。
- 已在中英文账号弹窗中提供 Endpoint、Region 和 AK/SK；请求固定使用路径模式，根目录默认展示 Bucket 列表，Session Token 暂不显示。
- 当前稳定性结论限定为“MinIO 路径模式已验证，可发布使用”；Amazon S3、Ceph RGW 和其他兼容服务尚未完成真实性验收。
- 已使用局域网 MinIO `http://192.168.0.105:9000` 的路径模式完成 Provider、Application、Transfer、Infrastructure 全链路真实性测试。
- Provider 重负载覆盖 205 个对象的前后翻页与搜索、1001 个对象及嵌套目录的重命名/移动、空文件、中文和特殊字符、同名覆盖、16 MB 多分片上传、进度及 SHA-256 校验。
- Application 覆盖连接测试、中文搜索、文本/图片流预览、文件重命名，以及包含 205 个对象的跨页递归目录删除。
- Transfer/Infrastructure 覆盖真实磁盘上传下载、并发数 6 下的 8 任务批次、pending 取消、认证失败后修正凭据重试、指纹开关、索引写入和重复上传查询。
- 运行中的 S3 上传或下载取消未纳入稳定能力；当前实现不保证请求已经进入 AWS SDK 后能够立即中断。
- 真实性测试发现并修复共享 S3 分页缺陷：过滤当前目录 marker 后不得提前读取并截断下一页，否则会丢失对象并导致递归删除假成功。对应单元回归已加入 `S3CompatibleProviderTests`。
- 真实性测试 Bucket 为 `atombox-v101-test`，代表性对象和每次运行的脱敏 manifest 保留在 `atombox/v1.0.1/e2e-<run-id>/`。
